# Push and email support in the candidate providers

Issue: jhomlala/cohort-005-project#7 (parent map #1). Researched 2026-11-12 from official docs, pricing pages and the WebKit blog only. Earlier findings (feed, auth, trigger APIs): `docs/research/notification-feed-providers.md` on branch `research/notification-providers`. Anything the fetched page did not state is marked **unverified**. Pricing changes; re-check before committing. Facts and trade-offs only, no decision.

Cadence context: `app/lib/mailer.server.ts` sends refund emails today through a `MailTransport` (Postmark REST call, or a `.outbox/` JSON file when no token is set). Email bodies are plain text only (`TextBody`), from `Cadence <hello@cadence.dev>`.

## Summary

- **Web push is not a first-class channel at Knock, Novu or Courier.** Each routes web push through a third-party push provider (FCM, OneSignal, Pushpad), which means Cadence owns the service worker, the permission prompt and the token registration. **SuprSend is the exception**: it documents its own web push channel (VAPID keys generated by SuprSend, service worker, `registerPush()`).
- **No provider requires a mobile app for web push.** Mobile-only providers (APNs, Expo) are separate. iOS limits come from Apple, not the providers: web push works only for a site installed to the Home Screen (iOS/iPadOS 16.4+).
- **Email: all four send through your own provider (Postmark, SES, Resend, SMTP...), none sends production email itself.** Cadence's existing Postmark account can be reused with all four, so a provider could replace `mailer.server.ts` for refund emails, at the cost of moving the copy into provider templates.
- **Preferences:** all four have per-channel and per-workflow/topic/category preferences with defaults and a "critical/required" override. Knock and Novu document it most clearly; SuprSend's pricing page lists User Preferences under the $250 Business tier (free-tier availability for the others is unverified).
- **Cost: every channel delivery counts separately on Knock and SuprSend (in-app + email = 2). Courier counts one template to one recipient as one send regardless of channels. Novu's counting rule was not verifiable.** All four free tiers are 10,000 units/month.

### Browser and iOS Safari limits (platform, not provider)

- Web Push on iOS/iPadOS needs 16.4 or later, the site added to the Home Screen as a web app (manifest `display` of `standalone` or `fullscreen`), and a permission request triggered by direct user interaction. The post does not describe support in plain Safari tabs. Uses Push API, Notifications API and Service Workers; no Apple Developer membership needed. Source: <https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/>
- HTTPS is required; localhost is exempt in most browsers (SuprSend doc). Prompts should follow a user action; a denial is hard to undo (SuprSend, Knock docs).
- Chrome only shows notification action buttons, max two (SuprSend, Novu/Pushpad docs).
- Trade-off: Cadence needs a Home Screen install story for iOS users regardless of provider; a PWA manifest is outside what any provider supplies (**unverified** that any provider ships one).

### Can it replace `app/lib/mailer.server.ts`?

- Transport: Postmark is a supported sender for Knock, Novu, Courier (and linked in SuprSend), so the existing Postmark account and verified `hello@cadence.dev` sender can be kept; the provider calls Postmark instead of `postmarkTransport`.
- What would move: subject and body copy (today in `refund-copy.ts` and the mailer) would become provider templates with variables, or be passed pre-rendered (Courier documents `html`/`text`/`subject` overrides; same for Novu/Knock is **unverified**).
- What would be lost: the `outboxTransport` local-dev behaviour (JSON files in `.outbox/`) and test fakes; the provider's own test or dev environment would need to substitute (see Novu/Knock environments, details **unverified**).
- Cost model: one refund event sent as in-app plus email is 2 messages at Knock and SuprSend, 1 send at Courier. Provider email billing is separate from the sender's (Knock, Courier docs).
- Trade-off: the direct mailer is a failure-isolated 40-line module with no third party in the data path beyond Postmark; routing email through the provider adds preference-awareness and one workflow definition per event, and puts user email addresses into the provider.

## Fit notes for Cadence

- Push needs, in every case, a service worker file served from the app root. In React Router this means a file in `public/` (or equivalent); the permission prompt must hang off a button (for example a bell menu "Enable push"), not page load.
- iOS students would only get push after installing Cadence to the Home Screen; Android and desktop browsers do not need that.
- Recipients to identify: push needs a per-browser token registered per user (Knock `setChannelData`, Novu credentials API, SuprSend SDK); with DevUI user switching the token should be re-registered or removed on switch (inference, not documented).
- Email addresses must be stored at the provider for the provider to send; Courier can send to a raw address instead but then preferences are skipped.
